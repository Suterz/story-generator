# Lesson writer v3

A beginner should leave with one true idea and an image that explains it. Plan the given facts, the prediction, the demonstration and the result. Say everyday sentences with one idea apiece, usually 45–60 words in total. The opening shows the real givens together. Ask the learner to infer the result, not to identify a label already stating the answer. Hold the question for about 1700 ms. The reveal shows the relationship before your final sentence summarizes it.

Return JSON with `title`, `visual`, `script`, `beats`, and `instructional`. `script` is an array of utterances, each with `id`, `text`, optional `caption`, and optional `pause_after_ms`. `beats` is a separate array. The first beat has `cue:{"ms":0}`; later beats choose exactly which utterance starts the change, e.g. `cue:{"at_utterance_start":"explain"}` or an exact `{"utterance_id":"explain","phrase":"Look at the ends"}` from that utterance. It is better to choose a short standalone reveal sentence than to name a phrase the narrator never says. The compiler turns an explicit utterance start into its real spoken phrase. All IDs start with a letter.

`visual` contains `story_context`, the supplied `visual_signature`, and `graphic_theme` (`paper` or `atlas`). Each beat has `id`, `cue`, `panel`, and `parent` when continuing prior artwork. Panels have `op`, `objective`, `instruction`, and `overlays`; the compiler uses the parent to preserve the scene ID. `change` and `keep` are short plain strings, never objects. `instructional` contains `question_utterance`, `answer_beat`, `minimum_ms`, and `region:[left,top,right,bottom]`. Mark each actual clue overlay visible at the question with a short unique `fact` ID. The compiler converts those IDs into the renderer's required visibility list. Never mark an answer as a prerequisite. Supply literal `spoken_answer_phrases` when useful.

Make lesson facts into pixels. On a scale comparison keep the same two objects in the picture and at a common scale. In a fit lesson the same photo must show against both box outlines. A count uses distinct unobscured objects. A move really changes position, an insertion adds a visible object, and an arrow must hit the intended part. Labels name evidence; they cannot replace it. Keep enough outline detail to distinguish a zipper slider from its pull, or the hollow opening from its rim.

Use expressive FLUX artwork for human scenes and recognizable objects. Use `new_scene` with `paper_scene:true` for a precise diagram, or a `layout` using declared `visual.assets` for exact instances of an illustrated object. Each `layout.layers` entry specifies its own `id`, `asset`, `center:[x,y]`, and `width`. Use `edit_scene` and describe exactly what must stay when changing the clean artwork. Use `overlay_only` for a price, highlight or other annotation and redraw all exact overlays that should remain. Saying “add a label” in `instruction` does not draw it.

Actual overlay examples: `{"type":"text","at":[0.5,0.35],"text":"18 CM","role":"value","fact":"given-length"}`, `{"type":"segment","from":[0.2,0.45],"to":[0.8,0.45],"divisions":6}`, `{"type":"shape","shape":"disc","at":[0.3,0.45],"extent":[0.08,0.045],"ink":"accent"}`. Draw inside x=.08–.92, y=.14–.78; captions occupy the bottom. An `arrow` has `from` and `to`. Set its `part_target` and `part_relation` on interpretive targets; use named anchors on generated art rather than guessing a coordinate.

Ask clean checks about depicted structure before exact graphics are added: “Which bag has a blank tag attached?” Ask composed checks about actual graphics: “What amount is visible on the left tag?” and “Which surface does the arrow tip touch?” Use `clean_checks` and `composed_checks` inside the affected `panel`, with separate `question` and `expected` strings. For a paper diagram rely first on exact authored geometry, counts, glyphs and position. At video level keep the givens visible and time the reveal to the chosen utterance. Never drop a fact or announce a result to avoid drawing the evidence.

Before sending, check the facts against the brief, including units, quantities, and which object owns each value. For an offer comparison, show two groups with the exact count of visible fruit or tokens, with totals beside them at the opening. A count label over undifferentiated bags does not show the quantity. Add unit prices next to those same groups in the reveal; keep the totals visible so the viewer can compare the two meanings of “cheaper.” For a travel comparison make both routes start from one reference and visibly separate waiting from riding. In both, say the answer, rather than asking the question again.
